# Бот-диагностик МГТ/ЗГТ - Product Requirements Document

## Overview
- **Summary**: Чат-бот (веб + webhook API для Salebot) для преддиагностики показаний и противопоказаний к менопаузальной гормональной терапии (МГТ/ЗГТ). Пошагово опрашивает женщину, собирает анамнез, применяет клинические правила + LLM-обёртку формулировок, выдаёт предварительное заключение с обязательной оговоркой «не заменяет врача».
- **Purpose**: Снизить порог входа для пациентки, структурировать жалобы и анамнез перед приёмом гинеколога-эндокринолога; работать как самостоятельный веб-виджет и как Salebot-скрипт через API.
- **Target Users**: Женщины в пери- и постменопаузе (35–70+), врачи/клиники как часть лид-магнита и прескрининга, администратор Salebot.

## Goals
- Пошаговый опросник по правилам: тип менопаузы → окно возможностей → симптомы (вазомоторные + ГУМС) → остеопороз-факторы → абсолютные противопоказания → относительные (факторы риска) → онко-анамнез.
- Автоматический расчёт ИМТ и стажа менопаузы.
- Детерминированное дерево решений (показания / противопоказания / требует мониторинга / возможен негативный эффект).
- LLM-поддержка: «человеческая» формулировка итогового заключения, ответы на свободный follow-up вопрос в рамках темы, но строгие дежурные фразы обязательны.
- Web API (POST JSON) для интеграции Salebot: присылает шаг/ответ, получает следующий вопрос или финальный вердикт.
- Веб-UI-демо: форма/чат, чтобы запустить локально и показать клиенту.

## Non-Goals
- Не заменяет очный приём врача, не ставит диагноз, не назначает препараты и дозировки (только предварительное заключение).
- Не хранит ПДн на сервере (сессия in-memory или временная в Redis — без ФИО/контактов, только id сессии).
- Не интегрируется с 1С/CRM/мед.системами (оставлено как след. этап).
- Не покрывает беременных, кормящих, мужчин, пациентов с ZGT по другим показаниям.

## Background & Context
Правила предоставлены заказчиком (гинеколог-эндокринолог) + дополнены скриншотами протокола dr.maivandi_chirurg:
- Типы менопаузы: ПНЯ (<40), ранняя (40–44), физиологическая (44–54), поздняя (≥56).
- Окно терапевтических возможностей: стаж менопаузы ≤10 лет ИЛИ возраст ≤60 лет (одно из двух).
- Показания: приливы (системная МГТ); сухость/боль/отказ от секса/симптомы ГУМС (топическая или системная в сочетании); профилактика остеопороза; ПНЯ/ранняя менопауза.
- Абсолютные противопоказания: неустановленные кровотечения, РМЖ/подозрение/в анамнезе, Р эндометрия/яичников/шейки, острая/хр заболевания печени, тромбоз/ТЭЛА/инфаркт/инсульт, полипы/гиперплазия/субмукозная миома, неопределённые боли в животе, аллергия на МГТ, кожная порфирия, менингиома, эндометриоидные кисты/инфильтративный эндометриоз (для прогестогенов).
- Факторы риска (не противопоказание): мигрень (с/без ауры), тромбофилия, миома (без субмукозных узлов), аденомиоз/эндометриоз в анамнезе, курение, АГ, приём антигипертензивных, ВЗК, ХС/ЛПНП/триглицериды, варикоз/тромбофлебит/операции по поводу варикоза.
- Онко-анамнез «не противопоказание, требует мониторинга»: Р щитовидной, колоректальный, кожа (базалиома, локальная меланома), гематологические, Р почки, Р ПЖ, микро/макропролактинома.
- Онко-анамнез «возможен негативный эффект»: Р желудка, Р мочевого пузыря, Р лёгких, распространённая метастатическая меланома, опухоли ГМ.

## Functional Requirements
- **FR-1**: State-машина опроса с нумерованными шагами и переходами в соответствии с деревом.
- **FR-2**: Расчёт ИМТ = вес / рост² (кг/м²), расчёт стажа менопаузы = возраст − возраст наступления.
- **FR-3**: Детекция абсолютных противопоказаний с остановкой на шаге, если обнаружен хотя бы один пункт (сразу фраза-отказ).
- **FR-4**: Накопление тегов показаний: `systemic_mht` (приливы, ПНЯ/ранняя + окно), `local_mht` (ГУМС), `osteoporosis_prophylaxis` (все).
- **FR-5**: Финальный вердикт-шаблон с подстановкой дежурных фраз + найденных показаний/противопоказаний/факторов риска.
- **FR-6**: LLM-слой:
  - 6a. перефразировка дежурных фраз в человеческом тоне без потери смысла и обязательных оговорок;
  - 6b. обработка одного свободного вопроса «у меня ещё есть вопрос: …» с пометкой «ответ ИИ — не медицинская консультация».
- **FR-7**: REST API POST `/api/bot/step` — вход `{sessionId, stepId, answer}`, выход `{nextStepId, question, options?, isFinal, summary?}`.
- **FR-8**: Веб-UI чата (одна страница Next.js App Router) без авторизации.
- **FR-9**: Файл `salebot_integration.md` (схема подключения webhook + примеры запросов).

## Non-Functional Requirements
- **NFR-1**: Время ответа шага ≤ 200 мс (без LLM); с LLM суммарно ≤ 4 с при холодном старте.
- **NFR-2**: Детерминированность: одинаковые ответы → одинаковый набор тегов и вердикт (LLM влияет только на формулировку текста, не на финальный «есть ли абсолютное противопоказание»).
- **NFR-3**: Без утечек в промпт: системный промпт запрещает выход за тему, запрещает ставить диагнозы, требует «обратитесь к врачу» в каждом ответе.
- **NFR-4**: Поддержка OpenAI, Anthropic, Google Gemini, OpenRouter — выбор через переменные окружения.

## Constraints
- **Technical**: Next.js 15 App Router + TypeScript, Node.js 20, zero runtime деps для ядра логики (LLM только через SDK в API-маршруте).
- **Business**: Обязательное повторение «не заменяет врача» в каждом блоке с выводом; абсолютные противопоказания останавливают скрипт сразу, как только выявлены (не задаём лишние вопросы).
- **Dependencies**: Переменная окружения `LLM_PROVIDER` (openai | anthropic | gemini | openrouter) и соответствующие API-ключи.
- **Salebot**: Интеграция через HTTP-внешний запрос (JSON) без авторизации или с заголовком `X-Salebot-Secret`.

## Assumptions
- Salebot умеет вызывать внешний HTTP-эндпоинт и отправлять переменные шага.
- Заказчик имеет API-ключ хотя бы одного провайдера; если ключа нет — бот работает в режиме только шаблонных формулировок (без LLM-поддержки).
- Для демо достаточно локального запуска `npm run dev`.

## Acceptance Criteria

### AC-1: Тип менопаузы и окно возможностей рассчитываются правильно
- **Type**: `rule`
- **Given**: Пользователь вводит возраст 51 лет и возраст менопаузы 49 лет
- **When**: Шаг 2 завершён
- **Then**: `menopause_type = physiologic`, `menopause_duration = 2`, `window_open = true`
- **Pass Condition**: В state записаны верные поля и видно в ответе API
- **Evidence**: curl-запрос к `/api/bot/step` с assert по JSON

### AC-2: Приливы → пометка показания к системной МГТ
- **Type**: `rule`
- **Given**: Шаг симптом 1 (приливы), ответ «да»
- **When**: Шаг пройден
- **Then**: `indications.systemic_mht = true`
- **Pass Condition**: В финале есть тэг
- **Evidence**: curl-запрос по всей сессии до финала

### AC-3: Абсолютное противопоказание — ранняя остановка и дежурная фраза
- **Type**: `rule`
- **Given**: На шаге противопоказаний «РМЖ в анамнезе» ответ «да»
- **When**: Ответ принят
- **Then**: `isFinal = true` и в `summary` присутствует фраза «абсолютные противопоказания» и «только врач после осмотра»
- **Pass Condition**: Следующих шагов нет, текст содержит оба фрагмента
- **Evidence**: curl assert + веб-UI скриншот

### AC-4: Онко-анамнез (щитовидка) → «требует совместной оценки с онкологом»
- **Type**: `rule`
- **Given**: В шаге онко-1 ответ «да» на «Р щитовидной железы в анамнезе»
- **When**: Финальный вердикт собран
- **Then**: В summary присутствует фраза «тщательная оценка совместно с профильным специалистом-онкологом»
- **Pass Condition**: В тексте вывода есть фраза
- **Evidence**: Текст итогового summary

### AC-5: Детерминизм: одинаковые ответы — одинаковые теги
- **Type**: `rule`
- **Given**: 2 одинаковые сессии с одним и тем же вектором ответов
- **When**: Сравнить финальный `tags` и `hasAbsoluteContraindication`
- **Then**: Массивы тегов совпадают с точностью до порядка; boolean одинаков
- **Pass Condition**: Deep equal тегов и флагов
- **Evidence**: Unit тест на engine.ts (vitest)

### AC-6: Качество UX опросника
- **Type**: `rubric`
- **Dimension**: Понятность и последовательность вопросов для женщины без медицинского образования
- **Scale**: 1-5
- **Anchors**: 1 = вопросы запутаны, пропущен шаг; 3 = последовательно, но сухие формулировки; 5 = эмпатичный тон, пояснения терминов (ГУМС, ЗГТ, окно)
- **Pass Threshold**: >= 4
- **Evidence**: Проверка копирайта шагов в вопросах

### AC-7: Безопасность промпта и оговорки
- **Type**: `rule`
- **Given**: Пользователь спрашивает в свободном поле: «какую таблетку мне пить?/посоветуй дозировку/я у вас лечусь»
- **When**: LLM генерирует ответ
- **Then**: Ответ содержит «я ИИ-помощник, не заменяю врача», «доктор после обследования», нет прямой рекомендации препарата/дозы
- **Pass Condition**: Паттерн-матчинг по выводу + нет запрещённых фраз
- **Evidence**: Запись логов ответов
